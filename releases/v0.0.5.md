Rayact 0.0.5 adds a supported Windows x64 desktop target, native platform
views and text input, the file-based router, the expanded first-party module
set, and a substantially faster retained renderer and development pipeline.

Compared directly with the remote `v0.0.4` release object, this release changes
531 files with 35,884 additions and 2,934 deletions across the engine, packages,
platform shells, tests, tooling, and documentation. Engine module ABI: **5**.
Requires Node >= 22.

Supported platforms: **Android**, **iOS**, **macOS arm64**, **Windows x64**, and
**Web wasm32**. Linux x64 remains preview.

## Install

```sh
RELEASE=https://github.com/raythings/rayact/releases/download/v0.0.5
npx "$RELEASE/create-rayact-app-0.0.5.tgz" my-app --release-url "$RELEASE"
cd my-app
npm run dev
```

Rayact packages are not published to the npm registry. The GitHub release
contains the package tarballs, native prebuilts, dev apps, web hosts, release
index, signatures, and checksums.

## Windows desktop

- Windows x64 is now a supported prebuilt target:
  `@rayact/prebuilt-windows-x64` ships the Vulkan desktop host and headless
  `rayact_tool`.
- The portable `rayact-dev-app-windows-x64.zip` contains the launcher, fonts,
  selected native modules, and CEF runtime. Install or launch it with
  `rayact dev-app --windows`; `RAYACT_DEV_SERVER=<url>` opens the project
  directly instead of stopping on the launcher screen.
- The rlvk desktop backend now owns real GLFW/Vulkan surface creation,
  swapchain recreation, resize, minimize/restore, DPI scaling, and safe window
  placement. Windows retries device discovery when switchable-graphics layers
  hide every Vulkan adapter.
- Native Windows `TextInput` uses the platform text-service path, including
  focus, selection, keyboard input, and IME composition.
- Resize now updates the Vulkan swapchain, logical layout viewport, hit testing,
  platform-view frames, and responsive CSS in the same frame. The former black
  reverse-L bars and stale/warped WebView frames are fixed.

## Platform views, WebView, and text input

- Module ABI 3 introduced composited platform-view factories; ABI 4 added
  native visual handles and forwarded pointer/key input; ABI 5 added off-screen
  platform-view frame delivery. Compatibility ranges and generated capability
  metadata now derive from the native ABI header.
- `@rayact/webview` runs on Android WebView, iOS/macOS WebKit, Web, and Windows
  CEF. Windows uses windowless rendering and paints WebView frames at their
  actual renderer z-order, so rounded siblings, overlays, clipping, scrolling,
  transparency, and input behave like the other platforms instead of producing
  rectangular child-window cutouts.
- `TextInput` is a native platform view where the platform supplies a native
  editor. Focus and pointer arbitration no longer leaves either the WebView or
  the Rayact layer unclickable.
- Platform views receive live geometry and visibility changes during window
  movement, resize, scrolling, clipping, and layout transitions.

## First-party modules and autolinking

- Dependency-driven module discovery reads each installed package's
  `rayact.module.json`; explicit config can configure or disable a discovered
  module. Android registration sources, iOS sources/frameworks/resources,
  desktop libraries, Web scripts/WASM, permissions, and URL schemes autolink
  from the same manifest.
- New first-party packages cover barcode scanning, clipboard, haptics, image
  picking, linking/deep links, sensors, and WebView, alongside MMKV, Secure
  Store, Crash Reporter, and SVG.
- The official dev app now advertises and gates all 12 integrated/first-party
  capabilities instead of a stale six-module subset. Its generated metadata
  reports ABI 5 and includes Windows.
- Browser module scripts and side-module WASM are served and staged with their
  adjacent runtime files. Web MMKV and Crash Reporter persist through the Web
  host rather than silently falling back to process-only state.

## Router, navigation, and app structure

- New `@rayact/router` package with file-based routes, nested layouts, dynamic
  segments, not-found routes, typed href helpers, route-tree generation, and a
  Vite virtual entry.
- `create-rayact-app` includes a router template, and the bundler automatically
  selects `@rayact/router/entry` when the configured routes directory exists.
- Linking events and initial URLs feed navigation consistently across native
  and Web hosts.

## Renderer, layout, scrolling, and styling

- Layout is retained across commits and recomputed only for dirty subtrees.
  Native styles use a compact slab representation, reducing repeated parsing,
  allocations, and bridge traffic.
- Scroll layout and paint were reworked so nested clips, implicit content
  containers, hit testing, native views, and worker views share one geometry
  model.
- `FlatList` gains windowed virtualization backed by a Fenwick tree for variable
  row heights, stable chat/end anchoring, and fast offset lookup.
- CSS is minified as a build artifact, imported styles are revisioned for HMR,
  and responsive rules reflow continuously during desktop resize.
- Font and icon staging is deterministic across packaged desktop/mobile apps;
  Material icon metadata travels with prebuilts and unused font tables are
  removed from platform artifacts.

## Development server and developer tools

- The server produces platform-specific manifests and bundles for desktop,
  Android, iOS, and Web from one process. Module manifests, browser scripts,
  WASM side modules, CSS/assets, routes, and capability requirements are
  revisioned together.
- Desktop shortcuts launch with both `--dev-server` and `RAYACT_DEV_SERVER`, so
  macOS and Windows open the active project directly. Non-interactive flows can
  use the same environment variable with `rayact start --dev` or
  `rayact dev-app`.
- HMR works at module granularity with full-reload fallback; route-set, config,
  CSS, asset, and native-capability changes invalidate the correct caches.
  `POST /rayact/reload` and `GET /rayact/status` remain the scriptable control
  surface.
- Development bundles include the project overlay without requiring each app to
  install a second private copy of the launcher. Source maps, transformed source
  serving, React DevTools targets, console capture, element inspection, frame
  timing, and heap diagnostics share the CDP proxy.

## Release builds and distribution

- Release bundles use mandatory QuickJS bytecode and `.rayactpack`; development
  entry points are compiled out of release-only desktop and Web hosts.
- CSS minification, font slimming, dead dev-client removal, native stripping,
  and host/resource staging reduce installed and packaged app size.
- Maintainers build Android/Linux, macOS/iOS, Web, and Windows locally into one
  canonical release set. GitHub only downloads, verifies, and attests the exact
  indexed/checksummed assets; it does not rebuild them.
- The release set now records Windows support, the Windows prebuilt, and the
  Windows dev-app asset.

## Notable fixes

- Desktop startup finds project-owned native modules and icon resources from
  both source checkouts and installed/cached prebuilts.
- macOS dev-app navigation icons are staged with their lookup metadata.
- Mobile fetch, XHR, WebSocket, binary response, redirect, abort, and error
  behavior is normalized through the native network bridge.
- Native development clients correctly load CSS-bearing projects without
  leaking CommonJS export bindings into the platform bootstrap.
- `@rayact/clipboard` and `@rayact/linking` package tarballs now include their
  Android and iOS native sources required by `rayact prebuild`.
- Android barcode scanning uses the typed Google ML Kit Code Scanner API
  instead of brittle reflection against overloaded builder methods.
- File-based router manifests stay as real ESM for release bundling, while the
  native module-HMR host adapts them for QuickJS.
- `nanoid/non-secure` resolves to its Math.random ESM entry under QuickJS
  instead of the Node `crypto` build.
- Light/dark switches update in-place: card title colours and the navigation
  bar active indicator refresh with the new scheme without requiring a
  screen remount.
- Web host discovery no longer selects stale local release files after native
  host sources change.
- Native module hashes cover the generated Windows, Web, Android, Darwin, and
  iOS artifacts, and package verification rejects missing or stale payloads.

## Known limitations

- Windows is x64 only in 0.0.5; Windows arm64 builds remain a build-gate and are
  not published.
- The Windows WebView brings its CEF runtime through `@rayact/webview`, so apps
  that select WebView have a substantially larger installed/package footprint.
- Linux x64 remains preview. macOS prebuilts remain Apple Silicon only.
- iOS device dev-app builds are unsigned; Android release APKs still require a
  project signing configuration for store distribution.

Rayact 0.0.4 — the first release you can actually install.

0.0.3's packages were never published to npm, so its documented quickstart
(`npx create-rayact-app@0.0.3`) 404'd and scaffolded projects could not resolve
their own dependencies. 0.0.4 makes the GitHub release itself a first-class
install source, splits the build toolchain out of the GUI runtime, adds native
SVG, and lands a large CSS and documentation overhaul.

**43 commits, 251 files, +12,140 / −1,380** since `v0.0.3`.

Supported platforms: **Android** (arm64), **iOS**, **macOS** (arm64), **web**.
Linux is preview. Engine module ABI: 1. Requires Node >= 22 < 25.

## Install

Rayact ships as the tarballs attached to this release, not via the npm registry.
The scaffolder vendors them into your project so a plain `npm install` never
consults the registry for `@rayact/*`:

```sh
npx https://github.com/raythings/rayact/releases/download/v0.0.4/create-rayact-app-0.0.4.tgz \
  my-app --release-url https://github.com/raythings/rayact/releases/download/v0.0.4
cd my-app && npm run dev
```

Already downloaded the assets? Use `--release-dir <path>`. Add
`--vendor-prebuilts` to vendor the native engines too, for fully-offline
installs.

Docs: https://raythings.github.io/rayact/

# Changes since 0.0.3

## Distribution and install

- **`create-rayact-app --release-dir` / `--release-url`** — copies (or downloads
  and checksum-verifies against `release-set.json`) the release tarballs into
  `vendor/rayact_pkgs/`, then emits `file:` dependencies **plus** an `overrides`
  block covering every vendored package, so transitive exact-pinned `@rayact/*`
  ranges can never escape to the public registry. `--vendor-prebuilts` extends
  this to the native engines.
- **The three undeclared dependencies behind 0.0.3's install failures** —
  `@rayact/template-android`, `@rayact/template-ios` and `@rayact/dev-client` —
  are now declared in generated projects and checked by `rayact doctor`. The
  dead `bundledTemplateDir()` fallback (a path that never existed in published
  tarballs, turning a missing dependency into a confusing 404) is gone in favour
  of errors that name the missing package.
- **Node version is enforced at the CLI entry point** (>= 22 < 25) rather than
  relying on npm's passive `EBADENGINE` warning.
- **Signed release sets** — `release-set.json` is accompanied by an ed25519
  `release-set.sig`; `verify-release-set.mjs --require-signature` validates it
  against the public key committed in the repo. 0.0.3 shipped unsigned.
- Scaffolded apps start at their own version (`0.1.0`) instead of inheriting the
  framework version.

## Reproducible builds

**The repository builds from a clean `git clone --recursive` again.** Three
dependencies were unbuildable outside the original machine:

- **raysvg** had zero commits and no remote, referenced through `../../../raysvg`
  sibling paths. It is now a real repository vendored at `third_party/raysvg`.
- **The rlmt Metal backend** existed only as shim headers including an untracked
  directory outside the repo. The implementation, its transpile support and the
  forked raylib headers it compiles against now live inside `raylib-backends`.
- **quickjs** pointed at a commit (CDP debugger hooks) that upstream does not
  have; it now tracks a fork that does.

The Android prebuilt also moved from Docker to host Gradle by default — a native
NDK compile instead of a Linux VM — with `--docker-android` to opt back into the
reproducible container build.

## `rayact_tool` — headless build toolchain

Bytecode compilation and `.rayactpack` packing no longer require the GUI
`rayact_desktop` binary. The new **`rayact_tool`** links QuickJS only — no
raylib, raym3 or GL — so Android/iOS/web builds run on headless CI and don't
pull a ~27 MB GUI runtime in just to act as a compiler. It ships inside the host
prebuilts; the CLI resolves it via `RAYACT_TOOL_BIN` / `--tool-bin` → source
build → prebuilt → cache, falling back to the old host path with a deprecation
warning for pre-0.0.4 caches.

## Native SVG

**`<Svg>`**, backed by the new raysvg engine — retained scene graph, tessellated
fills and strokes, id-keyed animation channels — renders on **every** platform,
web included. Accepts a staged asset path or inline markup.

## CSS engine

- **CSS Color 4 everywhere**: `oklch()`, `oklab()`, `lab()`, `lch()`, `hwb()`,
  `color()`, `color-mix()`, in both modern and legacy syntax. Tailwind v4's
  OKLCH palette and shadcn-style HSL themes work unchanged.
- **CSS custom properties** with `var()` plus a runtime JS API —
  `setCSSVariable`, `setCSSVariables`, `resetCSSVariables`, `getCSSVariable`,
  `useCSSVariable`. Live re-theming re-resolves matched styles natively with no
  remount.
- **State pseudo-classes** `:hover`, `:active`, `:focused`, `:disabled`, plus
  the `state-layer-color` / `ripple-color` extensions driving Material-style
  hover and press feedback on any pressable view.
- **`@keyframes` animations** run on the render thread, including infinite
  loops, direction and fill modes — no JS per frame. A JS style write cancels
  the native track for that property.
- **Responsive `@media`** queries (width / height / orientation) re-evaluate
  live on resize and rotation, alongside the existing `prefers-color-scheme`.

## Components and API

- **`ScrollView`** gains an imperative handle (`scrollTo`, `scrollToEnd`) and a
  react-native-style **implicit content container**. `contentContainerStyle` was
  previously typed but never implemented, and children laid out directly in the
  viewport-sized scroll node were squeezed to fit instead of overflowing into
  scroll range.
- **`Pressable`** exposes `PressableStateCallbackType` to both `style` and
  `children` render props.
- **`useColorScheme()`** returns `'light' | 'dark'` (react-native parity); it
  previously returned the internal boolean.
- New CSS-variable hooks and theme exports (above), and `Svg`.

## Web

- **CSS imports now register stylesheets on web.** The virtual CSS module
  special-cased web to an empty module, predating the MEMFS asset preload, so
  `import './app.css'` was silently a no-op in the browser while working
  natively.
- **`rayact build --web` stages every runtime asset** — worker `.wasm`, images,
  CSS — into `app-assets.json`, not just CSS. Worker spawns previously failed on
  content-hashed asset paths.
- **WebGL2 host option** as a WebGPU fallback, **native wasm exceptions** (a
  single unparsable CSS token used to `abort()` the whole page via `std::stof`),
  **mouse-wheel scrolling**, a `POST /rayact/reload` endpoint for scripted
  reloads, and **browser-authoritative canvas resolution** so zoom, resize and
  fractional DPI stay crisp.
- A second **`rayact-web-pthreads-0.0.4.tar.gz`** host ships for apps using WASM
  workers, which need SharedArrayBuffer.

## Documentation

Effectively a rewrite, published at https://raythings.github.io/rayact/:

- **Per-platform build guides** — desktop, Android, iOS, web, Linux — none of
  which existed before.
- New guides for **styling** (including the literal-path rule for stylesheet
  imports), **Tailwind**, **animation**, **navigation**, **fonts & icons**,
  **workers/WASM** and **native modules**.
- The **component reference expanded from 4 components to all ~65 exports**,
  joined by a new `rayact/react` **API reference** and a **CSS support
  reference** (properties, selectors, at-rules, colour formats).
- A coverage gate (`check-api-coverage.mjs`) fails the docs build when an export
  goes undocumented, and the maintainer roadmap was quarantined out of the
  published site.

## Notable fixes

- **Android release APKs were unusable.** R8 stripped the JNI-callback bridge
  classes, so the engine threw `NoSuchMethodError` every frame from
  `nativeRenderFrame` and touch input was completely dead. Keep rules added.
- **Worker canvases now clip like any other component.** The draw-protocol
  replay painted as a post-tree sibling pass, so a worker view inside a
  `ScrollView` kept rendering where the card had scrolled away — spilling past
  its container and under the OS navigation bar. It now paints in-tree (the
  `View3D` pattern), inheriting the ambient scroll/overflow clip and the node's
  z-order.
- **All three GPU backends** (Metal, Vulkan, WebGPU) flush the vertex batch
  before scissor state changes; queued vertices could otherwise draw under the
  wrong clip rect entirely.
- **`@rayact/prebuilt-darwin-x64` and `-linux-x64`** were missing `resources` in
  their `files`, silently shipping without the bundled icon and emoji fonts.
- **The dev app and dev client reported 0.0.3.** The launcher renders the app
  shell's `BuildConfig.VERSION_NAME` / `CFBundleShortVersionString` and a
  hardcoded `rayactVersion` in each `DevClientBridge` — none of which the
  lockstep version bump covered, along with the native engine version header
  compiled into every binary and the CDP handshake user-agent. All are now
  owned by `bump-version.mjs`, so `--check` catches future drift.
- Release verification no longer demands artifacts for architectures the release
  doesn't ship, and the consumer-smoke project's tarball pins are covered by the
  lockstep bump.

## Known limitations

- **Percentage dimensions are not supported** — `width: 50%` (and Tailwind's
  fractional `w-1/2` utilities) parse as pixel values. Use flex
  (`flex-grow`/`flex-basis`), `gap`, or fixed sizes.
- **Android ships arm64-v8a only**; x86_64 emulator images are not built.
  Release APKs are debug-signed — fine for sideloading, configure your own
  keystore before store submission.
- **macOS prebuilts are arm64 only**; Linux is preview; Windows is not yet
  supported.
- iOS device builds are unsigned; the simulator works out of the box.
- Child and sibling CSS combinators are unsupported, so Tailwind's `space-x-*`
  and `divide-*` utilities are no-ops — use `gap-*` and `Divider`.

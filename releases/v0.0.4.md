Rayact 0.0.4 — the first release you can actually install.

0.0.3's packages were never published to npm, so its documented quickstart
(`npx create-rayact-app@0.0.3`) 404'd and scaffolded projects could not resolve
their own dependencies. 0.0.4 makes the GitHub release itself a first-class
install source, splits the build toolchain out of the GUI runtime, adds native
SVG, and lands a large CSS + docs overhaul.

Supported platforms: **Android**, **iOS**, **macOS**, **web**. Linux is preview.
Engine module ABI: 1.

## Install

Rayact is distributed as the tarballs attached to this release, not via the npm
registry. The scaffolder vendors them into your project so plain `npm install`
never consults the registry for `@rayact/*`:

```sh
npx https://github.com/raythings/rayact/releases/download/v0.0.4/create-rayact-app-0.0.4.tgz \
  my-app --release-url https://github.com/raythings/rayact/releases/download/v0.0.4
cd my-app && npm run dev
```

Already downloaded the assets? Use `--release-dir <path>` instead. Add
`--vendor-prebuilts` to vendor the native engines too for fully-offline installs.
Requires Node >= 22 < 25 (the CLI enforces this).

Docs: https://raythings.github.io/rayact/

## Highlights

### Installable, reproducible distribution
- `create-rayact-app` gains `--release-dir` / `--release-url`: copies (or
  downloads and checksum-verifies) the release tarballs into
  `vendor/rayact_pkgs/` and emits `file:` dependencies **plus** an `overrides`
  block covering every vendored package, so transitive exact-pinned `@rayact/*`
  ranges can never escape to the public registry.
- Scaffolds now declare `@rayact/template-android`, `@rayact/template-ios` and
  `@rayact/dev-client` — the three undeclared dependencies behind 0.0.3's
  install failures. `rayact doctor` checks for all of them, and a missing
  prebuilt now produces an error naming the package instead of a silent null.
- **The repository builds from a clean `git clone --recursive` again.** raysvg
  is a real repo vendored at `third_party/raysvg` (was a sibling checkout with
  zero commits), the rlmt Metal backend is vendored inside `raylib-backends`
  (was shims pointing outside the repo), and the quickjs pointer moved to a fork
  that actually contains its commit.
- Release sets are **ed25519-signed** by default (`release-set.sig`);
  `verify-release-set.mjs --require-signature` validates against the committed
  public key.

### `rayact_tool` — headless build toolchain
Bytecode compilation and `.rayactpack` packing no longer require the GUI
`rayact_desktop` binary. The new `rayact_tool` links QuickJS only — no raylib,
raym3, or GL — so Android/iOS/web builds work on headless CI. It ships inside
the host prebuilts; the CLI resolves it via `RAYACT_TOOL_BIN` / `--tool-bin` →
source build → prebuilt → cache, falling back to the old host path with a
deprecation warning for pre-0.0.4 caches.

### Native SVG (`<Svg>`)
raysvg — retained scene graph, tessellated fills and strokes, id-keyed animation
channels — renders on **every** platform including web. Accepts a staged asset
path or inline markup.

### CSS engine
- **CSS Color 4** everywhere: `oklch()`, `oklab()`, `lab()`, `lch()`, `hwb()`,
  `color()`, `color-mix()`, modern and legacy syntax. Tailwind v4's OKLCH
  palette and shadcn-style HSL themes now work unchanged.
- **CSS custom properties** with `var()` + a runtime JS API
  (`setCSSVariable`, `setCSSVariables`, `resetCSSVariables`, `getCSSVariable`,
  `useCSSVariable`) — live re-theming re-resolves matched styles natively, with
  no remount.
- **State pseudo-classes** `:hover`, `:active`, `:focused`, `:disabled`, plus
  the `state-layer-color` / `ripple-color` extensions.
- **`@keyframes` animations** run on the render thread (raym3), including
  infinite loops, direction and fill modes — no JS per frame.
- **Responsive `@media`** (width/height/orientation) re-evaluates live on
  resize and rotation.

### Components
- `Pressable` state callbacks (`PressableStateCallbackType`) for `style` and
  `children`.
- `ScrollView` gains an imperative handle (`scrollTo`, `scrollToEnd`) **and** a
  react-native-style implicit content container — `contentContainerStyle` was
  previously typed but not implemented, and children were squeezed to the
  viewport instead of overflowing into scroll range.
- `useColorScheme()` returns `'light' | 'dark'` (react-native parity; it
  previously returned the internal boolean).

### Web
- CSS `import` statements now register stylesheets on web instead of resolving
  to an empty module, and `rayact build --web` stages **every** runtime asset
  (worker `.wasm`, images, CSS) into `app-assets.json`.
- WebGL2 host option as a WebGPU fallback, native wasm exceptions (a single
  unparsable CSS token used to `abort()` the page), mouse-wheel scrolling, a
  `POST /rayact/reload` endpoint, and browser-authoritative canvas resolution.
- A second `rayact-web-pthreads-0.0.4.tar.gz` host ships for apps using WASM
  workers (SharedArrayBuffer requires it).

### Documentation
Effectively a rewrite: per-platform build guides (desktop/Android/iOS/web/Linux),
a real getting-started tutorial, and new guides for styling, Tailwind,
animation, navigation, fonts & icons, workers/WASM and native modules. The
component reference expanded from 4 components to all ~65 exports, joined by a
new `rayact/react` API reference and a CSS support reference. A coverage gate
fails the docs build when an export goes undocumented.

## Notable fixes
- **Android release APKs were unusable**: R8 stripped the JNI-callback bridge
  classes, so the engine threw `NoSuchMethodError` every frame and touch input
  was dead. Keep rules added.
- **Worker canvases now clip like any other component** — the draw-protocol
  replay painted as a post-tree pass, so a worker view inside a `ScrollView`
  kept rendering where the card had scrolled away, spilling past its container
  and under the OS navigation bar. It now paints in-tree (the `View3D` pattern),
  inheriting the ambient scroll/overflow clip.
- All three GPU backends (Metal, Vulkan, WebGPU) flush the vertex batch before
  scissor state changes; queued vertices could otherwise draw under the wrong
  clip rect.
- `@rayact/prebuilt-darwin-x64` and `-linux-x64` were missing `resources` in
  their `files`, silently shipping without icon/emoji fonts.

## Known limitations
- **Percentage dimensions are not supported** — `width: 50%` (and Tailwind's
  fractional `w-1/2` utilities) parse as pixel values. Use flex or fixed sizes.
- Android ships **arm64-v8a only**; release APKs are debug-signed (fine for
  sideloading, configure your own keystore before store submission).
- macOS prebuilts are **arm64 only**; Linux is preview; Windows is not yet
  supported.
- iOS device builds are unsigned — simulator works out of the box.

## Verifying this release

```sh
shasum -a 256 -c SHA256SUMS
node scripts/verify-release-set.mjs <download-dir> --require-signature
```

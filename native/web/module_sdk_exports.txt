# Web module SDK surface — symbols the host exports to dynamically loaded modules.
#
# A web module is an Emscripten SIDE_MODULE (packages/<pkg>/web/*.wasm). Emscripten
# externalises the C++ runtime: a side module does not carry its own libc++/libc and
# imports it from the host instead. Anything listed here the host is guaranteed to
# provide; anything a module imports that is NOT listed fails at dlopen with an
# unresolved-import error naming the mangled symbol.
#
# This is therefore an ABI contract, not an implementation detail — removing a line
# can break an already-shipped third-party module. Treat it like a .def file:
# additive changes are safe, removals are breaking.
#
# NOT listed (deliberately): raysvg, raylib, raym3 and every other engine symbol.
# Modules reach the engine only through the RayactHost function-pointer table in
# native/core/rayact_module_abi.h — that indirection is what keeps this surface
# small and stable. @rayact/svg proves it works: it statically links its own copy
# of raysvg into its side module and imports nothing engine-specific.
#
# Verified by test/prebuild/web-module-abi.test.mjs, which builds every first-party
# web module and asserts its host-required imports are a subset of this list.
#
# Regenerate the raw candidate list for a module with:
#   node tools/web/module-imports.mjs <module.wasm>
